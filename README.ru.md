# DC-UPS-2CH — ESP32-контроллер резервного питания для сетевого оборудования

> Двухканальный DC-ИБП для домашнего Wi-Fi роутера и ONT/оптического
> терминала. Собран из готовых модулей: AC/DC-блок 24 В, зарядный XL4016,
> герметичный аккумулятор AGM 12 В 7 А·ч и два выходных XL6009 buck-boost.
> Контроллер ESP32 отвечает за защиту, веб-панель, уведомления через
> `ntfy.sh` и приём read-only команд статуса обратно через тот же topic.

**Версия прошивки:** `2026.09.02-v6` · **Лицензия:** [GPL-3.0-or-later](LICENSE)
· [English README](README.md)
· [Полный паспорт и руководство (LaTeX)](docs/DC_UPS_documentation_v6.tex)

## Зачем это нужно

На даче Wi-Fi + оптический ONT должны переживать короткие пропадания сети.
Готовые DC-ИБП физически переключают питание, но не сообщают ничего: нет
уведомления о пропадании света, нельзя перезапустить только ONT, если у
провайдера моргнул WAN, и защиту от глубокого разряда толком не настроить.

Здесь железо остаётся простым — только готовые модули с любого маркетплейса,
а логика вся в прошивке ESP32:

- автоматическое переключение сеть ↔ АКБ через общую 13,8 В шину (без реле);
- LVD с настраиваемыми порогами и гистерезисом восстановления;
- **два независимых DC-выхода** (ROUTER, ONT) с ручным ON/OFF/AUTO для каждого
  и раздельным restart;
- автоматический контроль связи и поэтапное восстановление (restart ONT →
  restart роутера → оба → при необходимости reboot ESP);
- push-уведомления через [ntfy.sh](https://ntfy.sh/) — отключения, LVD, boot,
  autorecovery;
- read-only команды через тот же ntfy topic: `!ups`, `!ups status`, `!ups ping`;
- локальная веб-панель + mDNS: `http://dc-ups.local/`;
- сервисный captive portal AP (`DC-UPS-Setup`), если WiFi не настроен или
  пропал;
- два режима глубокого сна: аварийный (проверка сети по таймеру) и
  Shelf Sleep (просыпается только кнопкой — для хранения/перевозки).

## Схема на пальцах

```
230 В AC ─▶ AC/DC 24 В ─▶ XL4016 CC/CV ─▶ 13,8 В шина ◀─▶ AGM 12 В 7 А·ч
                                                │
                            ┌───────────────────┼───────────────────┐
                            ▼                                       ▼
                    P-MOSFET + XL6009                       P-MOSFET + XL6009
                            │                                       │
                            ▼                                       ▼
                          ROUTER                                  ONT / AUX
                            ▲                                       ▲
                            │                                       │
                            └── GPIO32 ─── ESP32 ─── GPIO26 ────────┘
                                              │
                                              ▼
                                      ADC ◀── 24 В шина и АКБ
                                              │
                                      Кнопка ─┘ (GPIO14, EXT0 wake)
```

Полный BOM, распиновка, калибровка: [`docs/HARDWARE.md`](docs/HARDWARE.md).

## Архитектура прошивки

Прошивка сознательно не тянет внешних библиотек — только Arduino-ESP32 core.
Код разбит на маленькие модули, а общее состояние объявлено в
`include/ups_common.h`:

| Модуль            | Ответственность                                                            |
|-------------------|-----------------------------------------------------------------------------|
| `main.cpp`        | только `setup()` и `loop()`                                                 |
| `ups_common.*`    | пины, таймеры, enum-ы, `Config`, общие утилиты                              |
| `config_store.*`  | загрузка/сохранение в NVS `Preferences` + валидация                         |
| `hardware.*`      | LED, конечный автомат кнопки, обработка причины wake-up                     |
| `power.*`         | управление нагрузками, LVD, режимы каналов, планировщик power-cycle         |
| `wifi_mgr.*`      | STA/AP, captive portal, mDNS, ручной и автоматический reconnect             |
| `ntfy.*`          | исходящие сообщения + опрос команд (без сторонних HTTPS-библиотек)          |
| `sleep_modes.*`   | аварийный deep-sleep + Shelf Sleep, работа с RTC-памятью                    |
| `recovery.*`      | probe интернета (TCP 1.1.1.1:443 / 8.8.8.8:53) + поэтапное восстановление   |
| `web_ui.*`        | `WebServer` handlers + встроенная HTML/CSS/JS-панель                        |
| `event_log.*`     | кольцевой журнал в RAM                                                      |

## С чего начать

### Что понадобится

- ESP32 DevKit v1 (ESP-WROOM-32, USB-C или micro, CH340/CP2102 — оба ок)
- [PlatformIO Core](https://platformio.org/install/cli) (или расширение VS Code)
- Остальное железо — см. [`docs/HARDWARE.md`](docs/HARDWARE.md)

### Сборка и прошивка

```bash
git clone https://github.com/YOUR_USER/dc-ups-2ch.git
cd dc-ups-2ch

# Всё сразу (прошивка + PDF), с версией + git hash + датой в каждом артефакте:
make                   # то же, что make all
make upload            # прошивка + flash
make monitor           # 115200

# Или через PlatformIO — pre-скрипт всё равно проставит идентификаторы:
pio run
pio run -t upload
pio device monitor
```

Версия, которая попадает в прошивку и в оба PDF, берётся из файла
`VERSION` в корне репозитория плюс `git rev-parse --short HEAD` и
сегодняшняя UTC-дата. Её видно в serial boot log, в шапке веб-панели, в
ответах статуса ntfy и на наклейке корпуса. Можно переопределить:

```bash
make VERSION=2026.10.01-v7            # поднять версию для релизной сборки
make DOCREV="Rev. 3"                  # переопределить ревизию документа
```

`make version` показывает, что именно будет проставлено, `make help` —
все таргеты.

### Первый запуск

1. Если WiFi не настроен или сохранённые креды не подошли, устройство
   поднимает открытую точку **`DC-UPS-Setup`** с паролем `dc-ups-setup`.
2. Подключаемся телефоном/ноутом, идём на `http://192.168.4.1/`, вписываем
   SSID/пароль домашнего WiFi и topic для `ntfy.sh` (**topic —
   фактически секретный URL, придумайте длинную несловарную строку**),
   сохраняем. Устройство перезагружается.
3. Дальше панель доступна по `http://dc-ups.local/` (mDNS) или по IP,
   который ESP32 присылает в ntfy при каждом успешном подключении.

### Кнопка GPIO14

| Жест                     | Что делает                                                         |
|--------------------------|--------------------------------------------------------------------|
| 1 короткое нажатие       | отправить полный статус в ntfy (2× зелёный = отправлено)           |
| 2 коротких нажатия       | запустить setup AP на 15 минут (оба LED мигнут вместе)             |
| Удержание 10 с           | Shelf Sleep — всё OFF, просыпается только следующим нажатием       |
| Нажатие в Shelf Sleep    | штатный boot                                                       |

### Команды ntfy

Отправить в свой topic (из ntfy-приложения или `curl`):

```
!ups          # или "!ups status" — ответит полным статусом
!ups ping     # ответит "PONG ..." + статус
```

Устройство опрашивает topic примерно раз в 15 секунд, пока онлайн.
Управляющих команд через ntfy **нет намеренно** — topic только для чтения
статуса.

## Безопасность

Внутри корпуса живое 230 В. Не вскрывать при подключённой сети и не
отсоединив аккумулятор — SLA-АКБ выдаёт сотни ампер КЗ. Порядок разборки и
замены АКБ — в русском паспорте и в
[`docs/HARDWARE.md`](docs/HARDWARE.md#safety).

## Развитие

Issues и PR приветствуются. Условия:

- прошивка собирается на закреплённой платформе `espressif32@^6.9.0` (там
  устоявшийся watchdog и RTC-GPIO API);
- без новых внешних Arduino-библиотек — всё, что нужно, уже в core;
- новые функции — в отдельный модуль, а не в `main.cpp`.
